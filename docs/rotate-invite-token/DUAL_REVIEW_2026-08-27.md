# 초대 링크 회전 — dual-review 경위 (2026-08-27)

리뷰가 10라운드를 넘겨 경위를 남긴다. 요약이 아니라 경위다 —
**무엇을 고쳤고, 그 수정이 무엇을 깨뜨렸는지**를 라운드별로 적는다.

## 미정이었던 규칙 한 문장

> **초대 링크의 최신성을 어디까지 보장할 것인가.**

3라운드부터 7라운드까지 이 한 문장이 정해지지 않은 채였고,
그것이 드러나는 표면(조회 시점 → 요청 경합 → 메뉴 생명주기 → 포커스 → 타이머)을
라운드마다 하나씩 막았다. 7라운드에서 **"보장하지 않는다"** 로 정하자 그 계열의 지적이 한꺼번에 사라졌다.

이 문장을 3라운드에 썼다면 4~7라운드는 없었을 가능성이 크다.
"연쇄 2회면 패치를 멈추고 규칙부터 정한다" 는 지침이 가리키는 지점이 정확히 여기였다 —
5라운드에서 이미 "직전 라운드의 수정이 만든 결함" 이 2회 연속이었다.

## 두 리뷰어가 갈린 지점

- **초대 수락의 원자성**: codex 는 여러 라운드에 걸쳐 HIGH~MEDIUM 으로 반복 제기했고,
  claude 는 "주석이 한계를 정직하게 적어 두었다" 며 문제 삼지 않았다.
  최종 판단은 codex 쪽이 옳다 — 다만 근본 해결이 초대 라우트 재설계라 별도 작업으로 미뤘다.
- **`?error=constructor` 로 홈이 production 에서 500** (claude 단독, MEDIUM):
  `in` 연산자가 prototype chain 을 훑는 문제. **로컬에서는 재현되지 않고 배포본에서만 터진다.**
  이 MR 과 무관한 기존 결함인데 같은 hunk 를 건드리다 발견됐다.
- codex 는 경합과 원자성에, claude 는 접근성·i18n·라이브러리 실제 동작 확인에 강했다.
  같은 코드에서 서로 다른 결함을 잡았다.

- 복사 후 1.5초 안에 회전을 누를 때의 포커스 (LOW)
